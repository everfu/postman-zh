# 安装、切换与恢复

项目入口：[中文说明](../README.md) · [English](../README.en.md) · [兼容性记录](./compatibility.md)

## 安装前

- 本机已经安装官方 Postman。默认检查 `/Applications/Postman.app` 和 `~/Applications/Postman.app`。
- 保存正在编辑的请求、脚本与其他内容。安装器只会正常退出应用，不会强行结束进程。
- 安装目录需要当前用户可写，磁盘需至少预留约应用大小三倍的空间。
- 先阅读本页的应用签名说明。受管理设备可能不允许本地修改应用。

## 双击安装

1. 从 [Releases](https://github.com/everfu/postman-zh/releases/latest) 下载 `postman-zh-macos.zip`。
2. 解压并保留整个 `postman-zh` 文件夹。
3. 双击 `postman-zh.command`。脚本会退出 Postman、备份、生成补丁、校验并重新打开应用。
4. 按 `⌘ ,`，在设置右侧的“界面语言”中选择语言，再点“保存并重新加载”。

若 Finder 无法运行 `.command` 文件，在终端进入解压目录并执行：

```sh
bash ./postman-zh.command --install --quit --open
```

脚本不要求全局安装 npm 依赖。有 Node 22+ 时优先使用它，否则尝试 Postman 自带的 Node 运行环境。内置运行环境不可用时，需要另装 Node 22+。开发所需版本是 22.12+。

## 语言与账号的区别

“简体中文”只控制本机界面。“跟随官方语言”则恢复 Postman 原来选择的 English 或日本語。

“常规”页原有的语言设置会同时影响官方界面与邮件；中文模式下它显示为“官方语言（含邮件）”。本工具的开关不会替你修改该选项，也不会发送账号语言变更。

保存前请先保存工作内容。当前窗口会重新加载，其他窗口需要自行重新加载或重启应用。原生菜单跟随本地偏好更新；切回原版时菜单恢复为原版英文标签。

## 命令参数

| 参数 | 行为 |
| --- | --- |
| 无参数 | 安装，附加正常退出和重新打开 |
| `--install` | 安装或更新补丁；同一内容不重复注入 |
| `--restore` | 恢复当前安装记录对应的完整原版应用 |
| `--check` / `--status` | 只读检查应用结构、签名及备份 |
| `--app 路径` | 指定 Postman.app |
| `--backup-dir 路径` | 指定备份根目录 |
| `--quit` | 尝试正常退出应用；未退出则停止操作 |
| `--open` | 操作成功后重新打开应用 |
| `--version` / `-v` | 查看工具版本，不修改应用 |
| `--help` / `-h` | 查看帮助，不修改应用 |

带参数运行时，`--quit` 与 `--open` 不会自动附加。

```sh
./postman-zh.command --install --app "$HOME/Applications/Postman.app" --quit --open
./postman-zh.command --status
```

## 完整恢复

双击 `恢复原版.command`，或运行：

```sh
bash ./postman-zh.command --restore --quit --open
```

恢复会还原整份应用，包括原始签名和运行时标志；不删除 Postman 的数据库、请求、集合、历史记录。恢复不读取翻译词典，词典缺失也不应阻止恢复。

备份和本地语言偏好保留，默认位置为：

```text
~/Library/Application Support/PostmanZH/
├── language.json
└── backups/
    └── <版本>-<随机标识>/Postman.app
```

使用过自定义 `--backup-dir` 时，之后检查、更新和恢复都要传入相同参数。不要移动安装后的应用、删除原版备份，或编辑应用资源中的 `postman-zh.json`。版本、路径与摘要不匹配时，安装器会拒绝覆盖。

## 应用签名与系统保护

修改已签名的应用资源后，无法继续保留原厂签名与公证身份。本工具对暂存副本执行本地 ad-hoc 重签，保留 entitlements，并移除该应用的 Hardened Runtime 签名标志，以免缺少厂商 Team ID 的 Electron 框架被拒绝加载。

这些改动只针对被修改的应用。脚本不关闭系统 Gatekeeper、SIP 或证书验证，不修改 Electron fuses，也不清除下载文件的隔离属性。完整原版备份保留其签名；恢复操作将其一并还原。

如果 macOS 或企业策略不允许启动修改后的应用，请停止使用补丁并恢复官方应用。项目不提供关闭系统保护的操作步骤。

## 常见问题

### 更新 Postman 后又变成英文

官方更新可能替换整个应用。重新运行安装器，为新版本生成单独备份。不要手动把旧备份覆盖到已更新的应用上。

### 应用正在运行，安装器拒绝继续

先保存工作内容并完全退出，或附加 `--quit`。若出现未保存提示，先在 Postman 中处理；安装器不会强制结束进程。

### 文件夹不可写或签名校验失败

安装器不会自行提权。使用当前用户有写入权限的官方安装副本；原应用本身签名异常时先恢复官方安装，再尝试汉化。

### 应用更新、移动后恢复记录不匹配

保留备份，不要修改摘要字段。优先使用对应版本的官方安装包恢复。不同版本之间不做强制回滚。

### 安装器被中断，留下锁或暂存目录

先确认没有安装器运行。残留锁的路径会出现在错误信息中；确认后移除对应的 `.postman-zh-*.lock` 再重试。

替换失败通常会自动回滚。若文件系统错误导致回滚未完成，脚本会保留暂存原应用并打印路径。不要删除这些文件；可以从保留的原版备份复制完整 `Postman.app` 恢复。

### 校验下载文件

从同一 Release 下载 `SHA256SUMS`，与两个 ZIP 文件放在同一目录，执行：

```sh
shasum -a 256 -c SHA256SUMS
```

如果只下载了工具 ZIP，可以只核对校验文件中对应的那一行。发布包内部另附 `MANIFEST.json` 与 `BUILD_INFO.json`，用于核对文件和源码版本。
