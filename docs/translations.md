# 翻译维护

## 数据分层

| 文件 | 用途 | 来源 |
| --- | --- | --- |
| `locales/zh-CN.json` | 按模块组织的远程界面翻译 | 上游快照，含本地修订 |
| `locales/scratchpad.json` | 本地轻量客户端的整串匹配 | 上游快照 |
| `locales/menu.json` | 原生菜单标签 | 上游快照 |
| `src/runtime/chrome.cjs` | 新增固定控件、图标提示和少量术语修正 | 本项目维护 |

翻译快照来源与许可边界见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。不要把第三方译文重新声明为本项目原创内容。

## 贡献翻译

1. 记录 Postman 版本、所在页面、原文、期望译文和复现步骤。
2. 先判断文案是否来自语言模块；优先修改对应键，不扩大 DOM 扫描范围。
3. 动态控件需要明确的组件边界。请求标签、集合名、环境名、响应字段都可能与英文界面词相同，不能做全局替换。
4. 保留 ICU/i18n 插值、HTML 标签、快捷键、变量名和动态数字。
5. 补充关键回归：中文显示、关闭覆盖后原文、相同文本的用户数据保持原样。

术语约定：请求头、请求体、快捷键、双栏视图、浅色/深色主题、密钥库。技术标识如 HTTP、JSON、Cookie、AI 与主题品牌可保留原名。

## 更新上游快照

- 固定到明确的上游提交或归档，记录来源和 SHA-256，不在安装时追随浮动 main。
- 对比模块和键的变化，保留本项目已修正的设置布局与术语。
- 不导入上游安装器，也不复制 Postman 原厂源码或英文语言包。
- 更新说明文件，运行 `npm run verify` 与发布包检查，再在独立 Postman 副本上验证。

安装器使用随包提供的快照，不在运行时自动更新翻译。上游支持的操作系统或版本范围不自动等同于本项目的[支持范围](./compatibility.md)。
